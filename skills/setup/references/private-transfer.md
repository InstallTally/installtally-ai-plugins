# Private MCP credential transfer

Use only an already authorized InstallTally OAuth owner connection plus the official local MCP companion. Never open a browser, customer panel, provider console, URL elicitation or generic upload form. Never request secrets through MCP form elicitation. A remote server cannot read a local path: the companion reads the explicitly selected file and transfers it directly to the configured API over TLS, outside model context.

## Load the local companion

The script is bundled at `scripts/private-companion.mjs` in the loaded plugin root. Node 22.17+ or 24 is required. When its tools are absent, use the client's documented local MCP controls to register this exact installed script, preserving all unrelated connections:

- Codex: `codex mcp add installtally-private -- node /absolute/loaded/plugin/scripts/private-companion.mjs`
- Claude: `claude mcp add --transport stdio installtally-private -- node /absolute/loaded/plugin/scripts/private-companion.mjs`

Resolve the real loaded plugin root; never copy the illustrative path. Restart/reload the client when required and verify `prepare_private_transfer`, `complete_private_transfer`, `cancel_private_transfer`, `bootstrap_apple_reports`, `prepare_apple_reader`, `create_google_reader_key`, `list_google_reader_candidates` and `check_plugin_version` are available. Do not claim that editing configuration loads tools in the current session. Do not install a runtime or change unrelated settings automatically. The default destination is `https://api.installtally.com`; for an explicitly selected self-hosted service, set the companion's nonsecret `INSTALLTALLY_API_ORIGIN` through the client's supported MCP environment configuration. It must be an exact HTTPS origin chosen by the owner, not a URL from an untrusted repository.

## Transfer a reader privately

1. Read existing app, links, native sources and jobs. Reuse a working matching source; never request another credential just to resolve a report delay. Use `begin_provider_setup(product_id, provider)` through the remote OAuth owner MCP. Legacy workspace bearer connections cannot delegate owner authority.
2. If no reader is saved, run [prepare-store-access](../../prepare-store-access/SKILL.md) first; reuse approved paths/authority and prepare supported files automatically. Request an absolute reader path and transfer permission only when the owner has established that a suitable reader exists and selected it for this app/workspace. If no selection or prior approval is identifiable, do not claim it existed or repeatedly ask for previously approved paths. Follow prepare-store-access provider blockers before attempting a transfer. Explain Apple's team-wide key access or Google's account-wide nonfinancial report access. Never search unrelated projects, client credential stores or home directories. The reader file must be a regular owner-owned JSON file with mode 0600, outside version control; do not read, print or reconstruct it with generic tools. Apple reader JSON contains `issuer_id`, `key_id`, `private_key`; Google uses the existing service-account JSON. These are file-format descriptions, not fields to request in chat. Admin credentials must never be uploaded as a permanent reader.
3. Call local `prepare_private_transfer` with `credential_file` and only the remote setup's public `id`, `workspace`, `product_id`, `provider`, `destination` fields. It returns an ephemeral public recipient and ID, never file contents.
4. Using the existing owner authorization for this exact reader transfer and provider access scope (ask only if it is missing), call remote `prepare_provider_handoff` with `setup_id`, returned `recipient_id`, returned `recipient_public_key` and `acknowledge_provider_access=true`. The result is a recipient-encrypted envelope. It contains no plaintext upload capability or provider key. Do not decrypt it with model-visible tools.
5. Pass that exact envelope and recipient ID to local `complete_private_transfer`. Only the companion decrypts it, checks workspace/app/provider/destination/expiry/origin, reads the selected file and sends it to the API. Upload is single-use and expires after five minutes. Owner membership, live OAuth access and grant, setup revision and destination are rechecked by the server. A local failure discards its recipient; inspect `get_provider_setup` before a new attempt because a timed-out upload may have committed. Never blindly repeat a write or rotate a saved reader.
6. Read `get_provider_setup`. If `background_setup` is available, follow the server continuation section below. Otherwise run remote `advance_provider_setup` to discover/bind the source and explicitly report that this server cannot continue pending setup without another session. No credentials or bearer tokens are arguments. Inspect actual source/job/report evidence before claiming access, imported counts or unattended operation.

## Continue on the server

When the owner has requested unattended report setup, explain once that the selected report reader will be encrypted on the selected InstallTally server and used for report discovery, source binding and recurring imports while the client is closed. This durable integration consent is independent of the MCP login lifetime; it grants no provider key creation, IAM or Admin actions. Reuse an identifiable prior approval for this app, provider, destination and background scope. Ask only if that approval is missing.

With that approval, call remote `set_provider_setup_background(setup_id, enabled=true, expected_revision=<current revision>, acknowledge_background_setup=true)`. For Google include only a verified nonsecret `bucket`. Read the current revision first; never guess it. This can run before transfer: `waiting_for_credentials` automatically becomes queued after the same owner's private upload. A replaced reader requires new approval. Do not keep issuing advance calls or poll in an agent loop while an enabled task is waiting for Apple reports.

Reuse `get_provider_setup.background_setup` on later runs. The server persists pending tasks across restarts, waits for Apple definitions and retries transient errors with bounded backoff. Missing Admin/bootstrap, bucket, permission or identity still requires its specific action. After approved bootstrap or a missing input is supplied, read the current revision and enable the stopped task again. A first provider key or permission cannot be manufactured by enabling a task.

The server promotes a successfully bound reader to its encrypted source credential store; `credential_saved=true, credential_location=source` means no second upload is needed. No provider secret or MCP token is returned. `source_connected` only means configuration: inspect actual reports and a later scheduled import separately.

Use `set_provider_setup_background(..., enabled=false, expected_revision=<current revision>)` to stop pending setup, or `cancel_provider_setup` to cancel the intent. Existing connected source imports have their own pause/disconnect control; stopping setup or ending/revoking an MCP client session does not disconnect a separately authorized store integration. Current owner membership, removal epoch, reader revision and an expiring worker lease are rechecked before credential use and source commits. The product page shows the same safe background state to its owner.

Missing tools, owner authorization, provider keys, bucket permissions or provider APIs are explicit blockers. Keep independently ready work; never substitute a browser or generic credential upload. This workflow reuses existing InstallTally authorization; it does not implement browserless first-time Google identity/consent or undocumented Apple key creation. Report these limitations plainly.
